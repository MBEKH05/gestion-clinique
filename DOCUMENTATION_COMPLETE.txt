3. SYSTEME D'AUTHENTIFICATION ET PERMISSIONS
================================================================================

--- JWT (JSON Web Tokens) ---
- Algorithme : HS256
- Duree token acces : 24 heures
- Duree token refresh : 7 jours
- Rotation des tokens : activee (nouveau refresh a chaque utilisation)
- Blacklist apres rotation : activee
- Stockage : localStorage
  - Cles : 'access_token' et 'refresh_token'
- Auto-refresh : intercepteurs Axios renouvellent sur erreur 401/403

--- ROLES UTILISATEURS ---
Il n'y a que DEUX roles :

1. Super Admin (is_superuser = True)
   - Acces COMPLET a toutes les fonctionnalites
   - Peut supprimer des devis
   - Peut activer/desactiver IPM et Assurances
   - Acces aux Categories, Statistiques, Detail de Prestation

2. Manager (is_superuser = False, authentifie)
   - Peut creer/modifier devis, patients, analyses, tarifs
   - NE PEUT PAS supprimer des devis
   - NE PEUT PAS activer/desactiver IPM/Assurances
   - PAS acces aux Categories, Statistiques, Detail de Prestation

--- PERMISSIONS DJANGO (backend/api/permissions.py) ---
- IsAdminUser : Superusers authentifies seulement
  Utilise pour : delete devis, activate/deactivate IPM/assurance, categories CRUD, statistiques
- IsAdminOrManager : Tout utilisateur authentifie
  Utilise pour : lecture et ecriture analyses, IPM, assurances, tarifs, patients, devis (sauf delete)
- IsAdminOrReadOnly : Lecture pour tous, ecriture pour admin (defini mais peu utilise)

--- PROTECTION BRUTE-FORCE (backend/api/security.py) ---
- Classe : RateLimiter
- max_attempts : 5 tentatives
- window_seconds : 300 secondes (5 minutes)
- lockout_duration : 900 secondes (15 minutes)
- Identification par IP (support X-Forwarded-For pour Nginx)
- Logs : security.log + console

--- MIDDLEWARE (backend/api/middleware.py) ---
1. InputValidationMiddleware
   - Verifie taille des requetes (max 10MB)
   - Valide le JSON entrant

2. DisableCSRFForAuth
   - Desactive CSRF pour /api/* avec Bearer token ou /api/auth/*

3. SecurityHeadersMiddleware
   - Ajoute headers securite :
     X-Content-Type-Options: nosniff
     X-Frame-Options: DENY
     X-XSS-Protection: 1; mode=block
     Referrer-Policy: strict-origin-when-cross-origin
     Cache-Control: no-store pour /api/*

4. MODELES BASE DE DONNEES
================================================================================

--- CATEGORIE ---
Table : categories
Cle primaire : nom (CharField 50, unique)
Champs :
  - nom (CharField 50) — ex: "analyses", "radiographie"
  - actif (Boolean, default=True)
  - created_at (auto_now_add)
Ordre : par nom

--- ANALYSE ---
Table : analyses
Cle primaire : id (CharField 50, UUID)
Champs :
  - id (CharField 50, UUID auto-genere)
  - nom (CharField 500)
  - categorie (CharField 50, default='analyses')
  - created_at (auto_now_add)
Ordre : par nom

--- IPM ---
Table : ipms
Cle primaire : id (CharField 50, UUID)
Champs :
  - id (CharField 50, UUID)
  - nom (CharField 255)
  - actif (Boolean, default=True)
  - created_at (auto_now_add)
Ordre : par nom

--- ASSURANCE ---
Table : assurances
Cle primaire : id (CharField 50, UUID)
Champs :
  - id (CharField 50, UUID)
  - nom (CharField 255)
  - actif (Boolean, default=True)
  - created_at (auto_now_add)
Ordre : par nom

--- TARIF ---
Table : tarifs
Cle primaire : id (CharField 50, UUID)
Champs :
  - id (CharField 50, UUID)
  - analyse (FK -> Analyse, CASCADE)
  - type_prise_en_charge (choices: 'IPM' / 'ASSURANCE', nullable)
  - ipm (FK -> IPM, CASCADE, nullable)
  - assurance (FK -> Assurance, CASCADE, nullable)
  - prix (Decimal 15,2, min=0)
  - created_at (auto_now_add)
Ordre : par -created_at
IMPORTANT : Les tarifs sont GENERIQUES et PARTAGES.
  - type_prise_en_charge='IPM' = s'applique a TOUTES les IPM
  - type_prise_en_charge='ASSURANCE' = s'applique a TOUTES les assurances

--- PATIENT ---
Table : patients
Cle primaire : id (CharField 50, UUID)
Champs :
  - id (CharField 50, UUID)
  - nom_complet (CharField 255)
  - matricule (CharField 100)
  - type_prise_en_charge (choices: 'IPM' / 'ASSURANCE')
  - ipm (FK -> IPM, SET_NULL, nullable)
  - assurance (FK -> Assurance, SET_NULL, nullable)
  - created_at (auto_now_add)
Ordre : par -created_at

--- DEVIS ---
Table : devis
Cle primaire : id (CharField 100)
Champs :
  - id (CharField 100)
  - numero (CharField 20, unique) — format : {annee}-{seq:05d} ex: 2026-00001
  - patient (FK -> Patient, CASCADE)
  - total (Decimal 15,2, default=0)
  - souscripteur (CharField 255, nullable)
  - taux_couverture (CharField 10, nullable) — ex: "80" pour 80%
  - date_creation (auto_now_add)
  - statut_paiement (choices: 'NON_REGE' / 'PARTIELLEMENT_REGLE' / 'REGLE', default='NON_REGLE')
  - date_paiement (Date, nullable)
  - commentaire_paiement (Text, nullable)
  - is_proforma (Boolean, default=False)
Ordre : par -date_creation
Note : L'annee dans le numero est hardcodee a 2026 dans le serializer

--- DEVIS LIGNE ---
Table : devis_lignes
Cle primaire : id (CharField 50, UUID)
Champs :
  - id (CharField 50, UUID)
  - devis (FK -> Devis, CASCADE, related_name='lignes')
  - analyse (FK -> Analyse, PROTECT)
  - prix (Decimal 15,2, min=0)
  - quantite (PositiveInteger, default=1, min=1)

6. SERIALIZERS BACKEND

Champs : nom, actif, created_at (read-only)

--- AnalyseSerializer ---
Champs : id, nom, categorie, created_at (read-only)
Validation nom : sanitize_string (max 200 car), obligatoire

id : auto-genere UUID si absent

--- IPMSerializer / AssuranceSerializer ---
Champs : id, nom, actif, created_at (read-only)
id : auto-genere UUID si absent

--- TarifSerializer ---
Champs : id, analyse (PK), type_prise_en_charge, ipm (PK, nullable),
         assurance (PK, nullable), prix, created_at
Validation prix : entre 0 et 1 000 000

--- PatientSerializer ---
Champs : id, nom_complet, matricule, type_prise_en_charge,
         ipm (PK, nullable), assurance (PK, nullable), created_at
Validation nom_complet : sanitize_string (max 200 car), obligatoire
Validation matricule : sanitize_string (max 50 car)

--- DevisLigneSerializer ---
Champs : id, analyse (PK), analyseId (read-only=analyse.id),
         analyse_nom (read-only), analyse_categorie (read-only), prix, quantite
to_representation() : supprime le champ 'analyse', garde analyseId

--- DevisSerializer ---
Champs : id, numero, patient (PK), patient_nom (read-only),
         patient_matricule (read-only), total, souscripteur, taux_couverture,
         date_creation, lignes (nested), statut_paiement, date_paiement,
         commentaire_paiement, is_proforma
numero et date_creation : read-only

--- DevisCreateSerializer ---
Memes champs + lignes en ListField(DictField) write-only
create() :
  - Genere numero = {annee}-{seq:05d} (annee hardcodee 2026)
  - Calcule total = somme(prix x quantite)
  - Cree Devis + DevisLigne pour chaque ligne
update() :
  - Supprime toutes les anciennes lignes
  - Recree les nouvelles
  - Recalcule le total

7. VALIDATEURS BACKEND (backend/api/validators.py)
================================================================================

--- sanitize_string(value, max_length=500) ---
- Convertit en string si necessaire
- Supprime les balises HTML/XML (protection XSS)
- Supprime les caracteres de controle (\x00-\x1f, \x7f-\x9f)
- Verifie la longueur max
- Detecte les patterns SQL suspects :
  UNION SELECT, INSERT INTO, DELETE FROM, DROP TABLE,
  EXEC, --, /*, ;, xp_, sp_
- Raise ValidationError si suspect

--- validate_numeric(value, min_value=None, max_value=None) ---
- Convertit en float
- Verifie min/max
- Raise ValidationError si invalide

--- validate_uuid(value) ---
- Valide le format UUID
- Raise ValidationError si invalide

--- sanitize_input(data, field_validators=None) ---
- Nettoie un dictionnaire entier de donnees
- Applique sanitize_string par defaut sur les champs string
- Ignore les cles de plus de 100 caracteres

14. FLUX DE DONNEES COMPLETS
================================================================================

--- Flux : Creer un Devis ---
1. Utilisateur remplit DevisForm (patient + analyses + taux)
2. Frontend cherche patient par matricule+nom dans le state :
   - Si trouve ET donnees changees : PUT /api/patients/{id}/
   - Si non trouve : POST /api/patients/
3. Frontend : POST /api/devis/ avec :
   {patientId, lignes:[{analyseId, prix, quantite}], souscripteur, tauxCouverture, isProforma}
4. Backend DevisCreateSerializer.create() :
   - Cherche dernier devis 2026-XXXXX -> incremente
   - Genere numero : {annee}-{seq:05d}
   - Calcule total = somme(prix x quantite)
   - Cree le Devis
   - Pour chaque ligne : cherche Analyse par analyseId -> cree DevisLigne
5. Frontend recoit le devis cree -> navigue vers /devis/:id

--- Flux : Facture Mensuelle ---
1. Utilisateur selectionne mois + type + entite dans DevisMensuel
2. Frontend : getDevisMensuels(mois, typePriseEnCharge, ipmId/assuranceId)
   -> filtre les devis du DataContext par month+year + type patient + entite
3. Frontend : GET /api/factures-mensuelles/numero/?mois=&annee=&typePriseEnCharge=&entiteId=
   -> recoit FACT-YYYY-MM-XXX
4. Affiche tableau recapitulatif avec montantCouvert par devis
5. Bouton PDF -> generatePDFDevisMensuel()

--- Flux : Suivi des Paiements ---
1. SuiviFactures monte -> GET /api/statistiques/paiement/?mois=&annee=
2. Backend groupe les devis par entite (IPM ou Assurance)
   - Calcule montantCouvert = sum(total x (1 - tauxCouverture/100))
   - Retourne {statistiques, factures}
3. Utilisateur modifie statut/date/commentaire dans la table
4. Bouton "Enregistrer" ->
   PATCH /api/devis/{id}/update_paiement/ pour chaque devisId de chaque facture modifiee

--- Flux : Tarification ---
1. Tarifs stockes avec type_prise_en_charge='IPM' (partages pour toutes les IPM)
   ou type_prise_en_charge='ASSURANCE'
2. getPrixAnalyse(analyseId, ipmId, assuranceId) dans DataContext :
   a. Cherche tarif avec typePriseEnCharge correspondant (IPM si ipmId, ASSURANCE si assuranceId)
   b. Si pas trouve : cherche avec ipmId/assuranceId specifique (ancien systeme)
   c. Retourne le prix ou 0

--- Flux : Cache Frontend ---
1. Premier chargement : charge tout depuis l'API, stocke dans localStorage
2. Chargements suivants (< 1h) :
   - Charge analyses, ipms, assurances, tarifs, patients, categories depuis le cache
   - Recharge toujours les devis depuis l'API (non mis en cache)
3. Cache expire ou invalide : recharge tout depuis l'API

--- Flux : Historique (pagination serveur) ---
1. Utilisateur ouvre /historique
2. GET /api/devis/?page=1&page_size=15&ordering=-date_creation&is_proforma=False
3. Reponse : {count: total, results: [15 devis]}
4. Affiche les 15 devis + pagination
5. Navigation de page : nouvelle requete avec page=N
6. Recherche : nouvelle requete avec search=terme (reset page=1)
   Recherche dans : patient.nom_complet, patient.matricule, devis.numero
